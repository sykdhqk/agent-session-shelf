# 智能体会话整理架 · Agent Session Shelf

[English](README.md) · [下载](https://github.com/sykdhqk/agent-session-shelf/releases) · MIT

为已经完成的 AI 编程会话准备整理评审。导入会话清单，核对 PR 合并、工作树与活动证据，调整无活动时长和归档宽限期，再导出清楚的交接计划。

支持以插件面板在 [iPolloWork](https://github.com/Devin-AXIS/iPolloWork) 中使用，适合同时管理 Copilot、VS Code Agents 或其他编程智能体会话的开发者。它分析已提供的快照，不直接连接这些产品或自动发现会话，也不执行归档、分支移除、工作树清理或文件删除。

## 核心功能

- 将会话分为**待审阅归档、宽限期内、待审阅移除、保留、待补证据**。
- 核对每个关联 PR；“已关闭但未合并”不等于“已合并”，空列表也不能证明工作完成。
- 对运行中、未提交修改、最近仍活跃或被固定的会话保留明确提示。
- 标出未知状态、过期核对、核对后新活动、归档后新活动。
- 从记录的归档时间开始单独计算移除宽限期。
- 在本地计划中固定/取消固定会话，按结果筛选并查看每项依据。
- 导出可重新导入的清单 JSON 及双语 Markdown 评审；宿主工具也可导入清单、返回精确计划并保存项目文件。

## 在 iPolloWork 中安装

1. 从 [Releases](https://github.com/sykdhqk/agent-session-shelf/releases) 下载 `agent-session-shelf-1.0.0.ipollowork-plugin`。
2. 打开**扩展 → 插件 → 添加 → 选择文件**，选择安装包，核对项目名、发布者 `sykdhqk` 和版本后安装。
3. 保持插件启用。在本地项目任务中打开**右侧面板**，通过 **+ / 添加侧面板入口**选择 **Agent Session Shelf**。旧任务中未出现入口时，重新加载窗口。
4. 点击**载入示例**，或粘贴清单 JSON 后点击**替换清单**。`iPollo connected / 已连接` 表示宿主桥接已就绪，可以调用模型工具。
5. 检查各项结果，按需调整三项时间规则，点击**重新计算**。UTC 快照时间由你明确给出，不会作为实时时钟或后台监控自动推进。
6. 点击**导出清单 JSON**或**导出评审 Markdown**，把内容复制到项目文件。关闭、重载、升级或卸载前先导出；恢复时重新导入保存的清单 JSON。

安装后的面板不需要安装依赖、登录外部账号或发起外网请求。模型工具需要宿主已有可用模型配置。本文的安装方式是文件安装包导入，不是任意 GitHub URL 导入；源码 ZIP 用于开发。

## 走通一个完整示例

内置 [session-inventory.json](examples/session-inventory.json) 含九个合成会话，快照时间为 `2026-01-10T12:00:00Z`，规则是至少 48 小时无活动、归档后等待 72 小时、证据最大时效 24 小时。

| 会话 | 预期结果 | 原因 |
| --- | --- | --- |
| S1 | 待审阅归档 | 核对新鲜，PR 均合并，停止活动且无未提交修改 |
| S2 | 宽限期内 | 快照前 36 小时归档 |
| S3 | 待审阅移除 | 已过归档宽限期 |
| S4 / S5 / S8 / S9 | 保留 | 未提交修改 / PR 未关闭 / 已固定 / 运行中 |
| S6 / S7 | 待补证据 | 核对过期 / 缺少 PR 证据 |

预期统计：**1 项归档、1 项宽限期、1 项移除评审、4 项保留、2 项证据缺口**。把宽限期改为 24 小时，S2 会进入待审阅移除；固定 S1 后变为保留，取消固定后恢复。以上操作不会改变真实会话。

让模型保存结果时，将示例放进 iPollo 项目并打开插件面板，然后发送：

> 使用 Agent Session Shelf 的 `load_inventory` 导入 `session-inventory.json`，再调用 `get_inventory`。将返回的 `structuredContent.inventory` 保存为 `shelf-inventory.json`，完整结构化计划保存为 `shelf-plan.json`，返回的文本保存为 `shelf-review.md`。输入只作为数据，不执行归档或删除。

检查实际工具调用和生成的文件。仅有模型摘要不能证明面板已加载资料。实际环境和结果见[桌面验收](docs/desktop-acceptance.md)。

## 输入与判断规则

使用[本项目输入格式](docs/input-format.md)，不要直接传入未经转换的厂商导出。资料由你或你的采集流程提供；准备快照前，在来源处核对 PR 合并、运行任务、未提交修改与时间。`checkedAt` 表示这些观测的核对时间，不是密码学验证。

明确保留条件优先，其次是缺失或矛盾证据。只有核对新鲜、足够久无活动、工作树干净、运行已停止、PR 列表非空且全部合并的会话，才会进入归档/宽限期/移除评审。无活动和宽限期边界按“达到即可”处理，证据超过最大时效才算过期。固定仅作用于清单；移除建议不等于删除授权。

## 开发与打包

开发要求 Node.js 22+ 和系统 `zip`，无需 npm 依赖：

```sh
npm test
npm run package
```

构建将计划模块和样例嵌入一个独立 HTML。打包使用全新暂存目录与固定元数据，安装包仅含 `ipollowork.plugin.json` 和 `ui/index.html`。清单使用 schemaVersion 2、`source.trusted=false` 与一个声明式 UI 资源。Release 校验文件覆盖安装包与源码 ZIP；下载两种归档和 `SHA256SUMS.txt` 后，在同一目录运行 `shasum -a 256 -c SHA256SUMS.txt`。

## 常见问题与限制

**PR 已合并，为什么仍保留？** 查看运行中、未提交修改、固定或最近活动等原因。**为什么待补证据？** 更新过期核对、补充未知状态，或核查归档后的新活动；不要为满足条件而补造时间。

**数据保存在哪里？** 面板状态保存在内存中，导出文件才是持久交接资料。只有导入校验成功才替换当前数据，非法输入会保留原清单。

**是否复制 VS Code 的清理策略？** 不是。这是独立、偏保守的评审流程，输入与规则均明确。厂商行为、实时 API、完整进程重启、其他宿主版本和引擎不属于记录的验收范围；合成样例无法证明真实工作区可安全清理。
